### Describe the Bug

Crash on launch: FEX main entry fails at stage 3 (ENOSYS) during libSceNpToolkit2.prx init — SnowRunner (CUSA17425)

The app aborts (SIGABRT, exit code 134) ~3 seconds after launch, before the first frame is rendered. The crash occurs while `libSceNpToolkit2.prx` is being loaded, when several `libSceLibcInternal` HLE calls fail with errno 38 (ENOSYS). This cascades into a fatal `RunMainEntry` failure in the FEX linker.

- Device: Samsung Galaxy S26 Ultra (SM-S948N)
- SoC: Snapdragon 8 Elite Gen 5 for Galaxy (SM8850)
- Android: 16 (SDK 36)
- Guest backend: FEX
- GPU driver: system-vortek (host_api=1.4.0, box64Mode=HOST_GLIBC)

Game

- Fw/SDK: 0x9008000 / eboot SDK 0x9008001
- Network disabled in settings (`isConnectedToNetwork: false`, `isShadNetEnabled: false`)

### Additional notes
- Earlier in the same run there's a warning `ExtractTrophies: Failed to load npbind.dat file` — possibly related, since the crash happens specifically during NpToolkit init.
- Throughout the session there are ~349 recorded `signal=7 (SIGBUS) code=1` trap events, but these appear to be FEX's normal unaligned-access handling (execution continues after each one) rather than the actual cause — the fatal error is the `RunMainEntry` failure at the very end.
- Full diagnostic bundle (report.json, application.log, shadps4.log, session.json, process-exit.json, settings.json) available on request — report ID `BS4-20260812-969B2C19`.

### Suspected root cause
Incomplete FEX HLE thunk coverage for `libSceLibcInternal` functions required during `libSceNpToolkit2` static initialization, causing the guest main entry setup to fail fatally instead of falling back gracefully.

1. Launch SnowRunner (CUSA17425) with FEX backend + system-vortek driver, network features disabled
2. Wait ~3 seconds
