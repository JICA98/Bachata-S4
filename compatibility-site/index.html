The project

What is Bachata S4?

A PS4 emulator that runs on your phone

Bachata S4 adapts the shadPS4 emulator core to modern ARM64 Android hardware. PlayStation 4 software is built for x86-64 processors, so Bachata S4 runs PS4 game code through FEX, an open-source x86-64 emulator for ARM devices, inside a managed Linux (glibc) runtime packaged with the app. Graphics are rendered with Vulkan, using either the system's Vulkan driver or an explicitly selected driver such as Mesa Turnip.

Why it is experimental

PS4 emulation on Android is demanding: the emulator must translate game code, keep a full Linux environment alive, and drive a modern GPU in real time — all on mobile-class silicon and power budgets. Games that run on one phone may not run on another, and results can change with every release, driver, and thermal state. Treat compatibility reports as evidence for a specific configuration, not as promises.

Public source and evidence

The ARM64 emulator client and core remain open source. This release and community repository publishes the compatibility database, issue discussions, release notes, and downloads. Anyone can inspect report evidence or contribute a test of a game they legally own.

Reading reports correctly

Why results differ

Every report is a snapshot

A compatibility result describes one emulator release on one device on one day. The same game can behave differently depending on the Bachata S4 release, the SoC or CPU architecture generation, the GPU, the Android version, and the graphics driver — including the exact Turnip version when a custom driver is used.

Beyond the hardware

Results also vary with thermals (long sessions throttle mobile chips), the game update or version tested, and emulator settings such as resolution scale. Two phones with the same chip can still give different results because of cooling, firmware, and driver builds.

Check before you compare

Before trusting a report, match its release, device, driver, and game version against your own setup. If your result differs, that is normal — and the project would like to hear about it: new reports are how compatibility gets better.

Results can regress

Emulator development is not a straight line. A release that improves one game can change rendering or audio for another. That is why multiple reports per game are preserved instead of overwritten — history stays visible.

How testing works

Full methodology →

  1. 1

    Pick an official release

    Testers select a published Bachata S4 release — never a local or dirty build.

  2. 2

    Record the environment

    Exact device, SoC, GPU, Android version, and graphics driver (including Turnip version) are recorded up front.

  3. 3

    Test legally owned software

    Only software the tester legally owns is launched — games, or open-source homebrew.

  4. 4

    Publish evidence

    Screenshots, compressed logs, and measured performance are submitted for review before the report is merged.

Status meanings

Status definitions

Playable

Suitable for normal play in the tested configuration, with no major blocker found.

Ingame

Reaches controllable gameplay, but completion and full stability are not verified. Ingame is not the same as playable.

Menus

Reaches menus or title screens, but not controllable gameplay.

Boots

Starts and produces meaningful visual or audio output before an early blocker.

Nothing

Crashes, hangs, or fails to produce useful output in the tested configuration.
