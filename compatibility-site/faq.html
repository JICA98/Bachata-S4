Bachata S4 FAQ

Short answers to common questions about compatibility, Android hardware, graphics drivers, performance data, testing, and legal content.

What is Bachata S4?

Bachata S4 is an experimental open-source PlayStation 4 emulator project for ARM64 Android devices. It adapts the shadPS4 emulator core to Android and uses an x86-64 guest execution layer plus a Linux runtime and Vulkan rendering. It is early-stage software, so compatibility changes frequently.

Does “Playable” mean the game works on every phone?

No. A Playable label describes the configuration that was tested. The same title can behave differently with another Bachata S4 release, phone, SoC, GPU, Android version, graphics driver, game update, emulator setting, or thermal condition. Open the permanent CUSA page and compare the full environment before expecting the same result.

What is the difference between Playable and Ingame?

Playable means the tester found the title suitable for normal play in the tested configuration without a major blocker. Ingame means controllable gameplay was reached but significant problems can remain, including crashes, broken rendering, missing audio, poor performance, or progression blockers. Ingame should not be read as completion-tested.

Why does the exact Turnip version matter?

Turnip is a Mesa Vulkan driver used on supported Adreno GPUs. Different builds can change shader compilation, extensions, synchronization, rendering correctness, and performance. “Using Turnip” is therefore not specific enough for reproduction; the database records the version/build when available.

Is the system Vulkan driver always worse than Turnip?

No. Driver behavior depends on the device, Android firmware, GPU generation, game, and emulator release. Some titles may work better on the system driver, while others benefit from a particular Turnip build. Compatibility reports are evidence for a configuration, not a universal ranking of drivers.

Why can two phones with the same chipset get different FPS?

Cooling, power limits, RAM pressure, firmware, background tasks, screen resolution, driver build, and sustained thermal throttling can all change performance. Even identical hardware can produce different results if one test is short and cool while another is long enough to reach thermal limits.

What does an average FPS number actually tell me?

It tells you the average measured during that report's sample window. It does not guarantee the entire game runs at that speed. Scene complexity and frame pacing matter, and mobile devices can throttle over time. When available, also compare minimum/maximum FPS, frame-pacing notes, test duration, and resolution scale.

Why keep old reports after a new release?

History makes improvements and regressions visible. Replacing an old report with a new badge would hide whether behavior changed between releases or drivers. Permanent CUSA pages therefore preserve separate reports and tie each one to its own evidence.

Can I trust a report without screenshots or logs?

It can still be useful, but reports with evidence are easier to verify and debug. Screenshots show how far the game reached and reveal visual defects. Logs help developers identify whether a failure came from guest execution, system libraries, Vulkan, shaders, filesystem behavior, audio, or another subsystem.

Does Bachata S4 provide PS4 games, firmware, keys, or licenses?

No. Bachata S4 does not distribute games, firmware, decryption keys, licenses, or other copyrighted console content. Users are expected to provide software they legally own or are otherwise authorized to use, such as their own dumps or open-source homebrew.

How do I report a compatibility result?

Start by searching for the exact CUSA serial and existing discussion. A useful report includes the Bachata S4 release/commit, device, SoC, GPU, Android version, graphics driver, game version, relevant settings, observed status, performance measurements, and sanitized evidence from the same session. See How Testing Works and Contact.

Why does the site have both an interactive database and static game pages?

The interactive database is convenient for search and filtering. Permanent HTML game pages make each CUSA independently linkable, readable without JavaScript, and directly crawlable. They also keep the evidence and report history on a stable canonical URL instead of hiding the primary content inside a modal.
